W4A16 matmul

Decode multiplies a few activation rows by every weight matrix in the model, so it is limited by how fast the weights stream from DRAM. Storing weights as 4-bit integers (8 per int32, fp16 scale and zero per group of 128) cuts those bytes ~3.6x. The kernel dequantizes in registers and feeds tensor cores. For decode, split-K spreads one small matmul over the whole GPU. A CUDA C++ version of the decode case is compared side by side.

@triton.jit
def _w4a16_kernel(
    a_ptr, q_ptr, s_ptr, z_ptr, bias_ptr, c_ptr,
    M, N, K,
    stride_am, stride_ak, stride_qk, stride_qn, stride_sg, stride_sn, stride_cm, stride_cn,
    M_KEY,  # only used as an autotune key (M rounded up to a power of 2)
    GROUP_SIZE: tl.constexpr,
    HAS_BIAS: tl.constexpr,
    BLOCK_M: tl.constexpr, BLOCK_N: tl.constexpr, BLOCK_K: tl.constexpr,
    SPLIT_K: tl.constexpr, GROUP_M: tl.constexpr,
):
    # Grouped tile order so neighbouring programs share A rows / B columns in L2 (prefill).
    pid = tl.program_id(0)
    pid_k = tl.program_id(1)
    num_pid_m = tl.cdiv(M, BLOCK_M)
    num_pid_n = tl.cdiv(N, BLOCK_N)
    group_id = pid // (GROUP_M * num_pid_n)
    first_m = group_id * GROUP_M
    group_rows = min(num_pid_m - first_m, GROUP_M)
    pid_m = first_m + (pid % group_rows)
    pid_n = (pid % (GROUP_M * num_pid_n)) // group_rows

    offs_m = pid_m * BLOCK_M + tl.arange(0, BLOCK_M)
    offs_n = pid_n * BLOCK_N + tl.arange(0, BLOCK_N)
    mask_m = offs_m < M
    mask_n = offs_n < N
    offs_pk = tl.arange(0, BLOCK_K // 8)  # packed rows in one K tile
    shifts = (tl.arange(0, 8) * 4)[None, :, None]

    # This program's K range, aligned to BLOCK_K (BLOCK_K divides GROUP_SIZE divides K).
    k_tiles = K // BLOCK_K
    tiles_per_split = tl.cdiv(k_tiles, SPLIT_K)
    t_start = pid_k * tiles_per_split
    t_end = min(t_start + tiles_per_split, k_tiles)

    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)
    for t in range(t_start, t_end):
        k0 = t * BLOCK_K
        offs_k = k0 + tl.arange(0, BLOCK_K)
        a = tl.load(
            a_ptr + offs_m[:, None] * stride_am + offs_k[None, :] * stride_ak,
            mask=mask_m[:, None], other=0.0,
        )
        packed = tl.load(
            q_ptr + (k0 // 8 + offs_pk)[:, None] * stride_qk + offs_n[None, :] * stride_qn,
            mask=mask_n[None, :], other=0,
        )
        # [BK/8, BN] int32 -> [BK/8, 8, BN] nibbles -> [BK, BN], row k = 8 * packed_row + i
        q = (packed[:, None, :] >> shifts) & 0xF
        q = tl.reshape(q, (BLOCK_K, BLOCK_N))
        g = k0 // GROUP_SIZE
        s = tl.load(s_ptr + g * stride_sg + offs_n * stride_sn, mask=mask_n, other=0.0)
        z = tl.load(z_ptr + g * stride_sg + offs_n * stride_sn, mask=mask_n, other=0.0)
        b = (q.to(tl.float16) - z[None, :]) * s[None, :]
        acc = tl.dot(a, b, acc)

    if HAS_BIAS:
        if pid_k == 0:
            bias = tl.load(bias_ptr + offs_n, mask=mask_n, other=0.0)
            acc += bias.to(tl.float32)[None, :]

    c_ptrs = c_ptr + offs_m[:, None] * stride_cm + offs_n[None, :] * stride_cn
    c_mask = mask_m[:, None] & mask_n[None, :]
    if SPLIT_K == 1:
        tl.store(c_ptrs, acc.to(c_ptr.dtype.element_ty), mask=c_mask)
    else:
        tl.atomic_add(c_ptrs, acc, mask=c_mask, sem="relaxed")

CUDA C++ decode kernel (inner loop)

kernels/cuda/w4a16_decode.cu: w4a16_decode_kernel (70 lines, click to show)
__global__ void __launch_bounds__(kThreads) w4a16_decode_kernel(
    const half* __restrict__ x, const int* __restrict__ qweight, const half* __restrict__ scales,
    const half* __restrict__ zeros, const half* __restrict__ bias, half* __restrict__ out_f16,
    float* __restrict__ out_f32, int M, int N, int K, int group_size, int k_per_split) {
  __shared__ float xs[MT][kTileK];
  __shared__ float xsum8[MT][kTileK / 8];  // sum of each run of 8 activations (one packed row)
  __shared__ float red[MT][kColsPerBlock];

  const int lane = threadIdx.x % 32;
  const int warp = threadIdx.x / 32;
  const int n0 = blockIdx.x * kColsPerBlock + lane * kColsPerThread;
  const bool cols_ok = n0 < N;  // host checks N % 4 == 0, so a lane's 4 columns are all in or out
  const int k_begin = blockIdx.y * k_per_split;
  const int k_end = min(k_begin + k_per_split, K);

  for (int i = threadIdx.x; i < MT * kColsPerBlock; i += kThreads) (&red[0][0])[i] = 0.f;

  float acc[MT][kColsPerThread];
#pragma unroll
  for (int m = 0; m < MT; ++m)
#pragma unroll
    for (int c = 0; c < kColsPerThread; ++c) acc[m][c] = 0.f;

  for (int kt = k_begin; kt < k_end; kt += kTileK) {
    const int klen = min(kTileK, k_end - kt);  // multiple of 8
    __syncthreads();
    for (int i = threadIdx.x; i < MT * kTileK; i += kThreads) {
      const int m = i / kTileK, k = i % kTileK;
      xs[m][k] = (m < M && k < klen) ? __half2float(x[(size_t)m * K + kt + k]) : 0.f;
    }
    __syncthreads();
    for (int i = threadIdx.x; i < MT * (kTileK / 8); i += kThreads) {
      const int m = i / (kTileK / 8), r = i % (kTileK / 8);
      float sum = 0.f;
#pragma unroll
      for (int j = 0; j < 8; ++j) sum += xs[m][r * 8 + j];
      xsum8[m][r] = sum;
    }
    __syncthreads();
    if (!cols_ok) continue;

    for (int r = warp; r < klen / 8; r += kWarps) {
      const int krow = kt / 8 + r;
      const int4 q = *reinterpret_cast<const int4*>(qweight + (size_t)krow * N + n0);
      const int g = (kt + r * 8) / group_size;
      const uint2 s2 = *reinterpret_cast<const uint2*>(scales + (size_t)g * N + n0);
      const uint2 z2 = *reinterpret_cast<const uint2*>(zeros + (size_t)g * N + n0);
      const half* sh = reinterpret_cast<const half*>(&s2);
      const half* zh = reinterpret_cast<const half*>(&z2);
      const int qs[kColsPerThread] = {q.x, q.y, q.z, q.w};

#pragma unroll
      for (int c = 0; c < kColsPerThread; ++c) {
        const float s = __half2float(sh[c]);
        const float z = __half2float(zh[c]);
        float xq[MT];
#pragma unroll
        for (int m = 0; m < MT; ++m) xq[m] = 0.f;
#pragma unroll
        for (int i = 0; i < 8; ++i) {
          const float qv = static_cast<float>((qs[c] >> (4 * i)) & 0xF);
#pragma unroll
          for (int m = 0; m < MT; ++m) xq[m] += qv * xs[m][r * 8 + i];
        }
#pragma unroll
        for (int m = 0; m < MT; ++m) acc[m][c] += s * (xq[m] - z * xsum8[m][r]);
      }
    }
  }

Triton or CUDA?

Both kernels compute the same thing on the same weight format (int4 packed 8 per int32, fp16 scale and zero per group of 128), use the same factored dequantization, and pass the same tests. Numbers are from the final L4 runs (CUDA-graph timing, median of 3 sweeps); H100 numbers are on the site.

Speed. At batch 1 the Triton GEMV path reaches a median of 77% of peak bandwidth across six layer shapes, against 70% for the CUDA kernel (82% vs 74% on Qwen's gate_up layer). That was not true in the first round: the CUDA kernel led at batch 1 until both kernels got the factored dequantization and the Triton path picker stopped timing in eager mode (see DECISIONS). At batch 16 the gap is large: Triton holds 62% while CUDA drops to 29%. The CUDA kernel does its multiply-adds on CUDA cores, so 16 rows mean 16 times the arithmetic per weight and it becomes compute-bound; Triton switches to its tl.dot path on tensor cores. In the full model at batch 1: 118.2 tokens/s with Triton, 114.4 with the CUDA decode kernel. On the H100 the ranking is the same and the gap wider (batch 1: 25% vs 17% of peak, median; Qwen2.5 decode 398 vs 339 tokens/s): there, unpacking work rather than memory limits both kernels, and the CUDA kernel does more of it per byte.

Code. The Triton GEMM kernel is 58 lines and the batch-1 GEMV kernel 48. The CUDA kernel is 85 lines plus a 52-line host launcher with manual shape checks, alignment rules (N must be a multiple of 4 for 16-byte loads) and template dispatch on the batch size (scripts/loc.py). Triton's autotuner picked tile sizes, warps, pipeline depth, split-K and the dequant variant for every shape; for CUDA we tuned only split-K and hand-picked the rest. The Triton GEMM also covers prefill (batch 2048), which the CUDA kernel does not do at all.

When each is worth it. - Triton first: one kernel family for decode and prefill, autotuning for free, tensor cores without writing MMA code, and quick to iterate on. Here it ended up faster at every shape we measured. - CUDA C++ when you need control Triton does not give you: exact register tiling, vector widths, warp-level tricks, or a layout Triton cannot express. Our CUDA kernel would need a hand-written tensor-core (MMA) path to compete at batch 16, which is much more code. The CUDA version was still worth writing: an independent second implementation to check the numbers against, and for a while the faster one at batch 1, which is what pushed the Triton kernel to improve.

Power on L4

Sustained decode matmuls hold the card at its power cap (reason 0x4 = software power cap) and the SM clock drops well below its maximum. That is why sustained numbers sit below single-launch Nsight Compute numbers, and why cutting ALU work in the dequantization (the factored GEMV) raised bandwidth.
