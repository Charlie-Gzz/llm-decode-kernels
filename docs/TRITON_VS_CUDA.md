# Triton or CUDA C++ for the 4-bit decode matmul?

Both kernels compute the same thing on the same weight format (int4 packed 8 per int32, fp16 scale and zero per group of 128), use the same factored dequantization, and pass the same tests. Numbers are from the final L4 runs (CUDA-graph timing, median of 3 sweeps); H100 numbers are on the site.

**Speed.** At batch 1 the Triton GEMV path reaches a median of 77% of peak bandwidth across six layer shapes, against 70% for the CUDA kernel (82% vs 74% on Qwen's gate_up layer). That was not true in the first round: the CUDA kernel led at batch 1 until both kernels got the factored dequantization and the Triton path picker stopped timing in eager mode (see DECISIONS). At batch 16 the gap is large: Triton holds 62% while CUDA drops to 29%. The CUDA kernel does its multiply-adds on CUDA cores, so 16 rows mean 16 times the arithmetic per weight and it becomes compute-bound; Triton switches to its `tl.dot` path on tensor cores. In the full model at batch 1: 118.2 tokens/s with Triton, 114.4 with the CUDA decode kernel. On the H100 the ranking is the same and the gap wider (batch 1: 25% vs 17% of peak, median; Qwen2.5 decode 398 vs 339 tokens/s): there, unpacking work rather than memory limits both kernels, and the CUDA kernel does more of it per byte.

**Code.** The Triton GEMM kernel is 58 lines and the batch-1 GEMV kernel 48. The CUDA kernel is 85 lines plus a 52-line host launcher with manual shape checks, alignment rules (N must be a multiple of 4 for 16-byte loads) and template dispatch on the batch size (`scripts/loc.py`). Triton's autotuner picked tile sizes, warps, pipeline depth, split-K and the dequant variant for every shape; for CUDA we tuned only split-K and hand-picked the rest. The Triton GEMM also covers prefill (batch 2048), which the CUDA kernel does not do at all.

**When each is worth it.**
- Triton first: one kernel family for decode and prefill, autotuning for free, tensor cores without writing MMA code, and quick to iterate on. Here it ended up faster at every shape we measured.
- CUDA C++ when you need control Triton does not give you: exact register tiling, vector widths, warp-level tricks, or a layout Triton cannot express. Our CUDA kernel would need a hand-written tensor-core (MMA) path to compete at batch 16, which is much more code. The CUDA version was still worth writing: an independent second implementation to check the numbers against, and for a while the faster one at batch 1, which is what pushed the Triton kernel to improve.
